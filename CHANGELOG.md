# Changelog

## Unreleased

- **Fourth audit, of the whole plugin.** Deleting a task, or taking a parent off its day, no longer leaves its subtasks' lines indented under nothing, where Markdown reads them as code and Organized loses them (or under whatever todo happened to be above): they move out to the parent's level. Sorting a note that uses Windows line endings no longer mixes in plain ones when the last todo has no line break after it. Making a todo a subtask of one that sits inside its indented block (a numbered item with a two-space child) no longer fails with a `TypeError`; nothing moves. Starting or stopping the timer of a recurring task from the side panel now writes to today's todo even while the cursor is on another task in another note (before, today's note kept the old marker).
- **Third audit.** With *Delete expired tasks* on and *what to keep* set above title only, a finished task that has no todo line in any note was never cleaned up (the cleanup failed on it every time); it is now removed. One task note that cannot be written no longer stops the other tasks from following a renamed project or converted note; the failures are named in one notice. Regression tests in `bugHunt.dom.test.ts`.
- **More fixes from a second audit.** If a planned block ends while the todo line cannot be written (you are typing in that note), the task is ended again on the next pass instead of staying open with `[/]` in the note. A side panel brought back to the foreground after midnight repaints, so it no longer shows yesterday as today. A project budget of a few seconds is kept as one second instead of silently disappearing. In the project picker, Enter on a best match that is already picked keeps it picked (before it un-ticked it). Each has a regression test in `bugHunt.dom.test.ts`.
- **Fixes found by an audit of the 0.1.4 changes.** A task you put back to open during its planned block is no longer set in progress again by that same block (the block releases it when it ends). The checkbox of a recurring task with a running timer keeps its in-progress marker when you use `[+]`, `[t]` or cancel `[r]`. A secondary device is no longer told "did not add recurring tasks" while *Add missing recurring tasks* is adding them. A plugin switched off while Obsidian is still starting no longer leaves its minute check and focus listener running. Each has a regression test (`bugHunt.dom.test.ts`).
- New project skill `bug-hunt` (and a step in `release-stable`): an audit of the changes since the last stable release for what 100 % coverage cannot see, and every bug it finds is fixed with a test that failed before the fix.
- **Retiring tasks with 0.1.4 metadata.** A recurring task that is retired while its note stays now stops repeating (before, the next daily note brought its todo back); Undo gives the rule back. The Retire window's last line now says how many recurring tasks will stop repeating and how many planned blocks and time budgets are not kept when notes are stripped or trashed. Time worked that is kept under a retired todo now carries the task's projects as links, so project budgets (all time, this month) keep counting it; notes retired by earlier versions have no project and stay out of the budget.
- The onboarding tour (fresh installs) has three more cards for what 0.1.4 added: repeating a todo, planning time and setting a budget, and using several devices (Secondary and Mirror roles). It is now 15 cards, the most the tour allows.
- The What's new note now shows real crops of the plugin's own panel (the Recurring pill row, the Timer card with its budget bar, a planned block on the Day grid), in light and dark, instead of drawn sketches; the pictures for Settings and the command palette say where to find the thing in words. `npm run screenshots` renders the crops into `src/whatsNew/shots/` and they are bundled into `main.js` (about 150 KB).
- The pictures in the What's new note now say where each thing lives (the `[r]` marker and Recurring pill, the Day grid and Timer card, Settings › Organized › This device, the command palette) instead of only listing options; budgets and the repair commands got pictures too.
- **What's new** now shows the note of the running release only (what changed since the last stable one), both in the popup after an update and from *Show what's new*, instead of the history of the whole minor line. The 0.1.4 note is reorganised by benefit, with pictures for repeat rules, planned time and device roles. README screenshots show a repeating task, a time budget and a planned block.
- A subtask with a long title now wraps inside its row in the Task tab instead of running over the unlink button.
- On a phone, the day you paged to in the side panel's day view now opens as the daily note when you close the panel (paging itself still keeps the panel open).
- On a phone, paging through days in the side panel's day view no longer opens the daily note (which closed the panel after one day). Desktop still opens it.
- Project picker: the project row and the *Save links* button that have keyboard focus are now outlined, so Tab and the arrow keys visibly reach Save.
- **Calendar follows the daily note.** Switching to a daily note (for example after creating today's) now moves the side panel's calendar and day view to that day instead of leaving yesterday. Paging to another day in the day view opens that day's daily note when it exists; paging never creates one.
- **Fewer silent failures.** Task notes that are left out of the list (two notes sharing one id, such as a sync conflict copy, or a note with an id that cannot be read as a task) are now named in one notice per session, since those tasks otherwise just stop repeating. A secondary or mirror device says once per new daily note that it did not add the recurring tasks. Opening a daily note that holds the same recurring line twice (two devices both filled it) says so.
- **Two new commands.** *Add missing recurring tasks to this daily note* adds what is missing to the open daily note (today's when another note is open), for a note made while the plugin was not running or filled on another device. *Remove duplicate recurring lines in this note* removes the extra copies of a recurring line (open, unchanged, with nothing nested under them); it can be undone.
- Carrying unfinished tasks forward now also runs when the app comes back to the foreground with today's note open, so an app left open past midnight does not wait for another note to be opened.
- Project picker: the arrow keys now lead on from the last project to *Save links* and back (Enter saves from there), and Tab and Shift+Tab walk the search box, the projects and *Save links* in order.

- A todo's right-aligned properties that drop to a row of their own under a long title now stay right-aligned there (they were moved to the left edge in beta.16).

- **This device (Secondary and Mirror roles).** *Settings → Organized → This device* sets what a device may do with the vault, kept on that device only (it is not in the synced plugin data). *Secondary* edits tasks as usual but never creates or fills daily notes: no recurring tasks, no carrying unfinished tasks forward. *Mirror* only shows tasks: ticking, timers, scheduling and every other change are refused with a notice (shown once in a while, not for every keystroke), migrations and rename-following do not run, and the Day view does not create a day's note that does not exist. Use them on a phone or tablet that may open today's note before your main device has synced it, so two devices never write the same note.

- Fixed the right-align setting being ignored on phones (0.1.4-beta.15 put every todo's properties under its title). Right-aligned properties stay at the right edge again; only a group that finds no room beside its title and would drop to a row of its own, where it looked like part of the next todo, now sits under its own title from the left edge.

- Fixed a todo being ticked by mistake when the long-press menu on a phone is dismissed by tapping outside it: taps on the checkbox are ignored while the menu is open and for a moment after it closes.

- Fixed a todo's properties (project, priority) looking like they belong to the todo below when they did not fit on the title's line: such a group now sits under its own todo, from the left edge.

- Project picker: the list now stays inside the part of the screen the phone keyboard leaves free, so every project can be scrolled to; on a computer, the arrow keys move through the list, Enter ticks a project, Enter in the search box picks the best match and Ctrl/Cmd+Enter saves.

- A new daily note is now filled with recurring tasks only after it has stopped changing for a second, so a note another device is still syncing is not overwritten or doubled.

- **Follows the Daily Notes plugin.** Organized now takes the daily-note folder, filename format and template from the core Daily Notes plugin (or Periodic Notes, when its daily notes are on) instead of needing them copied into its own settings, so notes made by that plugin, or by another one that uses its setup such as a health-sync plugin, are the ones Organized sees. *Settings → Organized → Daily notes → Daily-note source* switches to custom settings; if neither plugin has a setup, Organized's own are used. An install that already saved a folder or format keeps it as custom, so nothing moves.

- Fixed recurring tasks adding one more copy of their heading to every new daily note when the note's template nests that heading under another one (for example `# Day` then `## Habits`, while the task remembers just `## Habits`): a task whose section is a single heading now goes under that heading wherever it sits in the note. Added tests for daily notes made by other plugins (Periodic Notes, Calendar, Templater-style rewrites, renames, back-filled and look-alike notes, other folder and date formats) and for templates with headings, callouts, code fences and duplicate headings.

- Fixed a new daily note missing some of its recurring tasks: if one task could not be written (the note was already open and being typed in, or a sync was writing it), the tasks after it were skipped and never retried. Each task is now added on its own, a failed one gets a second try, and any that still fail are named in one message. Added tests for sync and race cases: notes arriving from another device, overlapping rule changes, Windows line endings, front-matter-only notes, 60 recurring tasks at once, conflict copies of a task note and a task note edited by sync.

- Fixed the Repeat dialog showing today's weekday (or day of the month) for a task whose rule leaves that out, such as `recurrence: every 2 weeks` written by hand: it now shows the day the repeat actually started on, so saving without changes keeps the same days. Also hardened the repeat rules against dates before 1970, and added tests that check them against an independent reference over five years of dates, and the daily-note flow day by day.

- Tidied the Repeat dialog: shorter preset buttons (Daily, Weekdays, Weekly, Monthly, Yearly; hover shows the exact rule), "Every [number] [unit]" on one line, equal-width weekday buttons (M T W T F S S) and a divider above the plain-words result.

- **Repeat rules.** Typing `[r]` in a todo (or tapping the Recurring pill) now opens a Repeat dialog instead of switching repeating on and off: one-tap buttons for every day, weekday, week (on today's weekday), month (on today's date) or year, and below them a small form (*Every [3] [weeks]*, weekday buttons, day of the month) with the result read back in words. The rule is kept in the task note as `recurrence`; the task is added to the daily notes the rule produces, and the pill shows it. Tasks that only had `recurring: true` keep repeating every day. Stopping or changing a rule removes only future copies nobody has touched.

- Fixed a task started by its planned time sometimes showing in progress in the side panel while its todo kept `[ ]`: if the note changed at that moment (you were typing, or the editor saved older text over the change), the marker was lost and never retried. While a planned block is running the marker is now checked every minute and put back in every note that holds the todo; a status you chose yourself is never rewritten. Also fixed `[t]` (add time) turning `/` back into `[ ]` on a task started by a planned block, and forwarding or linking such a task to a project writing `[ ]` instead of `[/]`.
- Fixed a todo that only lives in an earlier daily note not showing its status: when it was set in progress (by a planned block, the timer or the side panel), done or canceled, its checkbox stayed `[ ]`. That line now follows the status. A todo that also has a line in today's, a later or an undated note keeps the old note as history, and forwarded `[>]`/`[<]` lines are never changed.

- **Fold Description, Subtasks and Timer.** Each of these task panel cards now has a chevron to fold it away; a folded card keeps a one-line summary (the first line of the description, `1 of 3 done`, the time tracked) and the choice is remembered for every task. The Timer is tighter: its start/stop, add time and budget buttons are small icons in the header row, and the budget bar no longer repeats the numbers already in the summary.

- **A denser task panel.** Priority, Schedule, Recurring and the linked projects now sit together as small icon pills in one wrapping row instead of a titled card each; project pills carry a faint tint of the project colour, are cut short when long and open the project note when tapped. The Timer card is one line (`4h tracked · 1h planned`) with Start, Add time and Budget side by side, and an empty Description is a single *Add description…* button. Same controls, much less scrolling on a phone.

- **One Add time dialog for worked and planned time.** Typing `[t]` in a todo, or choosing *Add time* in the phone long-press menu, now opens the same dialog as the calendar, and decides for itself: a block that has ended is saved as time worked, one still to come as planned time (the dialog says which). The task's Timer card has a single **Add time** button.

- Fixed a very small project budget (a few seconds) vanishing when saved, and a done or canceled task's leftover planned blocks counting against its own time budget (project bars already ignored them). Also: renaming or moving a project note now moves its tasks' links along (before, its budgets and colour stopped applying to them); time from a todo that became a standalone note keeps counting toward its project's budgets; and a project linked twice on a task is listed once.
- **Project time budgets.** A project note can set `organized_budget` (whole project) and `organized_budget_daily`, `_weekly`, `_monthly` (hours). Each task in the project shows a bar for every budget set, counting the time of all tasks in the project for that day, week, month or in total; the Timer card appears automatically. Set them from *Project budgets* in the Projects tab or in the note's properties. Projects without budgets show nothing.
- **Time budget for a task.** The Timer card has **Set budget** (hours and minutes). Once set, a slim bar compares tracked plus planned time with the budget: tracked time in your accent colour, planned time lighter, and the time still left in words. Past the budget the bar extends and the overrun shows in red, with "over budget" in words. No budget, no bar. Stored as an optional `time_budget_seconds` on the task note.
- **Plan your time ahead.** Time blocks can now be set aside for later, not only logged afterwards. Tap an empty spot on the Day grid (or use **Add time** with a time still to come) to block time for a task, on today or any day ahead. Planned blocks are drawn dashed next to tracked ones and never count as worked time. A planned block that is over can be logged as worked in one tap.
- **Tracked and planned, side by side.** The task's Timer card now has *Tracked so far* and *Planned*, so you can compare an estimate with what the work took.
- **Tasks start at their planned time (optional).** The new setting *Start tasks at their planned time* (Task behavior, off by default) sets a task in progress, without starting a timer, when its planned block begins, and puts it back to open with a notice when the block ends. A status you set yourself is never changed.

## 0.1.2

- The last card of the welcome tour no longer talks about "this beta".
- **No restart needed for the welcome tour or What's new.** They now open a moment after Organized is switched on or updated, instead of waiting for the next time Obsidian starts.
- **What's new after an update, the tour only for new installs.** After Organized updates you see a short note about that version, once (reopen it with *Show what's new*; switch it off under Settings → Help). The welcome tour now appears only on a fresh install, and has two new cards: press and hold on a phone, and jumping into a checkbox from the keyboard. If you updated from an older version you are no longer shown the tour; run *Show onboarding card* any time.
- **`[+]` adds a subtask.** Type `+` in a todo's checkbox, or choose *Add subtask* in the phone long-press menu, and an empty indented todo appears under it with the task picker open; the todo keeps its own status. A plain todo becomes a task first, as with the other markers. Not offered in Reading view.
- **Jump into a todo's checkbox from the keyboard.** The new command *Edit checkbox marker* puts the caret on the marker of the todo you are on, with the character selected, so the next key replaces it as if you had clicked into the checkbox. It has no default key; bind one in Settings → Hotkeys (for example `Alt+X`). Off a todo line it says so.

- **Projects explained.** The README has a short *Using projects* section (the `[j]` marker, why `[[Note]]` in a todo is only a link, and the one property, `organized_type: project`, that makes an existing note a project). The project picker now says why only some notes are listed and where a typed name creates a new note.
- Fixed the long-press menu opening for the wrong todo when you pressed a checkbox inside a rendered description: it is now ignored there.
- Fixed the long-press menu doing nothing on a nested (indented) subtask: it now works at any depth.

- **Long-press menu, rounded out.** Rows now have icons and the marker the todo has is ticked; on Android a short vibration confirms the press. It also works on Reading view checkboxes in daily notes (linked todos run the marker like a typed one; a plain todo can only be ticked, reopened or canceled). A new setting, *Long-press marker menu* under Task behavior, turns it off.

- **Long-press a todo on your phone to change its marker.** In a daily note on iOS and Android, press and hold a todo's checkbox and a menu offers the markers that act: open, done, in progress, cancel, forward, schedule, priority, star, description, sources, projects, recurring, convert to note and add time. Choosing one is the same as typing that letter in the checkbox, so pickers and status changes behave as usual; a plain todo that you tick or cancel this way stays a plain todo. Formatting-only letters are not listed. Desktop and Reading view are unchanged. This is new on touch screens, so feedback from real devices is welcome.

## 0.1.1

- Review fixes: the test tooling no longer uses `js-yaml` (replaced by `yaml`), two `:has()` selectors are gone (a focused description or source now highlights its card with `:focus-within`, and right-aligned symbols keep their line through a line class), and the README no longer contains template-looking text. ## 0.1.0

- **A clearer README.** It now says why Organized exists next to calendar and task plugins (and when it is not the right tool), and tours the side panel with numbered screenshots, including a task with nothing added to show how little a todo costs. The numbered pictures are rendered from the plugin's own code like the others.
- **Clear a date.** The schedule dialog (the `[<]` marker and the Schedule card) now has **Clear date** on a scheduled task: the date goes, a todo that was scheduled away reopens where it stood and the copy on the scheduled day is removed. The movement history keeps the record.
- **`[t]` logs time worked from the todo.** Type `[t]` in the checkbox and a dialog asks for a start and an end (on the day of the daily note), logs the block on the task and the calendar, and puts the todo's own marker back. Cancelling leaves the `[t]`.
- **A calmer time dialog.** The start and end of a block of time are now a date and a time side by side instead of one wide field that ran off the edge of a phone dialog, and no field takes focus on opening, so the system picker no longer pops up over the form.
- The onboarding card's checkbox-letter step now says the letters do what the panel does and shows eight of them, including `[t]` and `[r]`.
- **Unlink a subtask from its parent.** Every subtask row in the Subtasks card now has a small unlink button (*Remove … from this task*), so you no longer have to open the subtask to use **Remove from parent**. The todo stays where it is in your notes; only the link in the parent's properties goes.
- Fixed **Add subtask** in the Task tab failing with *Editor changed while the picker was open*: the side panel had taken focus from the note, which was mistaken for a change of note. A task created for a nested todo now also gets the projects of its parent (linking an existing task leaves its projects alone).
- **Movement history at a glance.** The collapsed *Movement history* list in the Task tab is now always visible as a strip of tiny squares, one per move, oldest first, with *Moved N times* above it. Squares turn from green through yellow and orange to red by how often the task was forwarded compared with what is usual for you, so a task you forward after two weeks stays green much longer than one you usually forward after three days. When enough tasks of the task's project were forwarded (five), the project's own habits set the scale. A date you picked yourself (*Schedule* or *Reschedule*) is drawn in your theme's accent colour. After three rows of ten, the squares become a slider showing how far the task is towards red. Hover a square or open *Details* for the exact moves; the strip is labelled for screen readers.
- The onboarding card now names the three icon buttons under a task's subtasks (new subtask, link a task, make it a subtask) in the illustration of the step about a todo growing, and its text says what they do.
- Release housekeeping: the Obsidian indent setting is now read through `normalizePath`, which the release check requires. Beta 77 was not published because of it; this beta carries its changes.
- **Subtasks are indented the way Obsidian's own Tab key indents.** Organized wrote two spaces, which Live Preview draws as a shallow shift rather than a proper nested list. It now writes one tab, or the spaces of your *Indent* setting when you turned off *Use tabs* (read from `.obsidian/app.json`), everywhere it indents a subtask: **Add subtask**, linking from the panel, and forwarding or scheduling a parent. Once after updating, subtasks that Organized had indented with two spaces get the same indentation (the old text of every changed note is saved in `note-backups` and the notice has **Undo**); **Indent subtasks under their parents** does it again on demand.
- **Linking a subtask from the panel now indents its todo.** **Link existing task…** and **Make subtask of…** move the todo (with everything nested under it) to sit under its parent in every note that has both, with a notice and **Undo**. Once after updating, subtasks that were linked before this change but still sit at the top of their list are indented the same way, after the old text of every changed note is saved in the plugin folder (`note-backups`); a notice has **Undo**. The command **Indent subtasks under their parents** runs it again. A todo already nested under another todo is left alone by the one-time step.
- **Subtasks in the panel.** The Subtasks card no longer picks up a phone theme's pill-shaped button styling: each subtask is a plain row with a round status toggle and its title. New buttons link tasks from the Task tab without touching any note: three small icon buttons in one row under the subtasks, each with a tooltip and screen-reader label: add a new subtask, **Link existing task…** (choose an open task to become a subtask of this one), and **Make subtask of…** (choose the parent for this task) or, on a subtask, **Remove from parent**. A task that is a subtask now always shows the card, and a task cannot be made a subtask of itself, of one of its own subtasks, or when it is recurring.
- Documentation and the onboarding card now describe subtasks: the feature table, the `[x]`, `[-]`, `[>]` and `[<]` marker rows, and the onboarding step about growing a todo.
- **Subtasks (third part): forwarding and scheduling a parent.** Forwarding (`[>]`, automatic carry-over to today) or scheduling (`[<]`, the panel) a todo takes its subtasks that are still open or in progress along: they get the new date and a movement entry, their lines in the old note turn into the forwarded or scheduled marker, and in the new note they sit indented under the parent. Done and canceled subtasks stay in the old note as the record (they still count in the parent's progress); a subtask below a done one goes under the nearest subtask that moved. A subtask forwarded or scheduled on its own goes under its parent when the new note has the parent, and at the end of the section otherwise; its place under the parent stays in the parent's properties. A manual move says what moved, with **Undo**; one subtask that cannot move is named and the rest still go.
- **Subtasks (second part): completing or canceling a parent.** Completing a todo now completes the subtasks under it that are still open or in progress (a running timer stops and its time is kept); canceling it cancels them. Done and canceled subtasks are never changed, subtasks below a done subtask are reached, and reopening or starting a parent changes nothing. One notice names the subtasks and has **Undo**, which puts the subtasks (not the parent) back. When every subtask is done but the parent is not, the Subtasks card offers **Complete parent**. Forwarding and scheduling a parent follow in the next beta.
- **Subtasks (first part).** Indent a linked todo under another todo and it becomes its subtask. The parent's task note lists its subtasks as links (`subtasks: ["[[Buy milk]]"]`); the nesting in your note stays the truth and the lists follow when you indent, outdent, move or delete lines, link a todo while it is nested, or convert a note's todos. New: the command **Add subtask**, the command **Repair subtask links in this note**, a *Subtask progress* symbol (`2/3`) in Rendered task properties, a **Subtasks** card and a *Part of* link in the Task tab, nested rows in the note list (a finished parent stays visible while something under it is still to do), and sorting that keeps subtasks among their own siblings. Renaming or deleting a subtask updates its parent's list, and deleting a parent says which subtasks stay. Completing, canceling or forwarding a parent does not touch its subtasks yet; that follows in the next betas.
- Fixed right-aligned symbols hanging into the line below when the todo text left no room for them: they sat next to the note under the todo and looked like part of it. They now stay inside their own todo's line (on a row of their own under the text), and a nested list in Reading view starts below them. The layout check reproduces the old behaviour and covers it.
- With *Alignment* set to the right edge, the symbols that every todo has (status, priority, star, recurring, created) now sit in one column at the edge, and what varies from todo to todo (project names, the number of moves, the time) is placed to their left, still against the edge. A forwarded todo's extra arrow no longer pushes the other symbols out of line.
- **Alignment of the symbols on a todo line.** A new setting under Settings → Organized → Rendered task properties, *Alignment*, puts the symbols (priority, star, recurring, time…) either right after the todo text (the default, as before) or at the right edge of the line. On a narrow phone screen the symbols drop to their own right-aligned row when the text leaves no room; descriptions and sources keep reading from the start. The layout check covers four widths, light and dark, left-to-right and right-to-left.
- Fixed the task dialog losing the first letter you typed into a new todo: the letter now stays in the search box, with the cursor after it, and the list is filtered by it.
- The picker that links a new todo to a task now lists only unfinished tasks (open and in progress). Completed and canceled ones no longer bury a chore you repeat under every time you did it; typing the title still offers **Create new task**.
- Fixed the task dialog not opening when you press Enter on a todo and start typing the next one. The blank `- [ ] ` that Enter leaves now asks (link a task, create one, keep a plain todo) when you type its first character; you no longer have to delete the space and type it again.
- **Faster with many tasks.** Drawing the panel no longer reads every task note from disk each time: the properties of a note are parsed once and reused until the note changes (any edit, rename, delete or sync drops them, and text you have not saved yet in an open task note is never reused). Typing in today's daily note used to redraw the panel on every autosave; it now redraws at most about twice a second. Task notes and the reference index are read several at a time at startup and on first use.
- Onboarding and README catch up with the compact symbols, the sort rule, the timer stop on removing `/` and the short time format; the onboarding illustration now shows the recurring symbol and `1h 13min`.
- Fixed todos showing "Missing task; repair via attach/create" right after starting Obsidian (beta 63 and later). A task looked up while the note index was still being built was reported missing; the lookup now waits for the build to finish.
- Fixed a timer that kept running after you changed or deleted the `/` of its `[/]` checkbox. It only stopped when the cursor was on that line and nothing else was running; now the timer stops (and a notice says so) whenever you turn `[/]` into `[ ]`, `[x]`, `[-]` or remove the slash, wherever the cursor is, and even while another action is in progress.
- **Existing task notes are renamed after their todo.** Once after updating, every task note still named after an id (`Tasks/9f3a…d1.md`) is renamed after its todo's title, oldest first, with a counter for duplicates and no clash with any other note in your vault. The planned renames are saved first in the plugin folder (`note-backups/task-names-…json`), the notice has **Undo**, time records of notes you converted stay as they are, and a note that cannot be renamed keeps its id and is named in the notice. The command **Rename task notes to their titles** tries again. Update Organized on all your devices together: an older version looks for task notes by their id.
- Fixed a gap in the id lookup of the previous beta: while the lookup was being rebuilt at startup, a task could briefly be reported as missing. The old lookup now keeps answering until the new one is ready.
- **Task notes are named after the todo.** A new task note is `Tasks/Write the Q1 report.md` instead of a 32-character id, so your tasks stay readable even if Organized is not installed. Names avoid characters Obsidian or your system reject, use a counter when a name is taken (`Plan`, `Plan 2`), and are unique across the whole vault so `[[Plan]]` never becomes ambiguous. Editing a todo's title renames its note. A task is identified by the `id` in its properties, not by its file name, so you can rename a task note yourself and everything keeps working (your name stays until the title is edited again). If two notes ever claim one id (a copied note, or an older Organized on another device repairing a task), neither is read or changed and the message names both. Notes that are still named after their id keep working and are renamed in the next beta; Retire only renames notes that still carry an id name.
- Durations over an hour are written the short way everywhere (`1h 13min`, `2h`, `45 min`): the Timer card, the symbols beside a todo, session lengths and the standalone-note dialog. Time written into a retired todo's notes uses it too, and the older spelling (`1 h 20 min`) is still read back.
